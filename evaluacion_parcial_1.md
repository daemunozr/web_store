## 2. Instrucciones Generales para el/la Estudiante

* **Descripción General:** Cada evaluación parcial es una parte del examen transversal, dividiendo el caso en tres entregas. La Evaluación Parcial 1 consiste en una entrega de encargo (proyecto e informes) y una presentación.
* **Contexto:** Desarrollo de un sitio web para una **tienda online** (basado en casos del docente o propuesta libre del equipo).
* **Modalidad:** Equipos de **máximo 3 estudiantes** en taller de alto cómputo.
* **Evaluación:** **Individual** tanto para el encargo como para la presentación.
* **Tiempo:** 1 semana.

---

## 3. Instrucciones Específicas de la Evaluación

### Situación Evaluativa 1: Entrega por encargo (40%)

1. **Estructura y Estilos Web:**
   * Crear contenido web con estructura y etiquetado **HTML5** válido (`<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<footer>`).
   * Incluir hipervínculos funcionales, imágenes correctamente insertadas, botones operativos, videos embebidos, formularios interactivos y un footer informativo.
   * Asegurar la interconexión y navegación coherente entre páginas.
   * Utilizar una **hoja de estilos CSS externa** para aplicar un diseño consistente.

2. **Validación con JavaScript:**
   * Validar los formularios mediante JS utilizando los elementos apropiados (etiquetas asociadas, autocompletar, sugerencias, etc.).
   * Prevenir el envío de datos incorrectos o incompletos.
   * Mostrar mensajes de error y sugerencias claros, específicos y contextualizados.

3. **Trabajo Colaborativo y Control de Versiones:**
   * Utilizar un repositorio de trabajo colaborativo.
   * Registrar commits con mensajes claros y descriptivos.
   * Distribuir tareas equitativamente entre los miembros e integrar los cambios de forma efectiva.

#### Documentos Requeridos y Entregables del Proyecto (Grupo):
* **Documento ERS (Especificación de Requisitos de Software) - Versión 1:**
  * **Requerimientos:** Necesidades, expectativas, funcionalidades, restricciones y requisitos técnicos.
  * **Herramientas:** Especificar software, plataformas y lenguajes de programación.
  * **Propuestas del Proyecto:** Ideas, enfoques y estrategias para cumplir con los requerimientos.
* **Entregables:**
  1. Enlace a repositorio **GitHub público** del proyecto frontend.
  2. Proyecto frontend comprimido.
  3. Documento ERS (propuesta previa, Versión 1).

---

### Situación Evaluativa 2: Presentación (60%)

Durante la presentación individual, cada estudiante debe:
1. Explicar la creación del contenido web con la estructura y etiquetado HTML actual, enfatizando la importancia de la **semántica correcta**.
2. Describir el uso de hojas de estilo **CSS personalizadas y externas** para lograr una interfaz atractiva, funcional y mantenible.
3. Describir cómo validó los formularios mediante **JavaScript** (etiquetas, autocompletar, mensajes de error y sugerencias).
4. Mostrar y justificar las operaciones realizadas en el **repositorio de trabajo colaborativo** (commits, distribución de tareas e integración).

## 4. Pauta de Evaluación (Rúbrica)

### Niveles de Logro

* **Muy buen desempeño (100%):** Demuestra un desempeño destacado, evidenciando el logro de todos los aspectos evaluados en el indicador.
* **Buen desempeño (80%):** Demuestra un alto desempeño del indicador, presentando pequeñas omisiones, dificultades y/o errores.
* **Desempeño aceptable (60%):** Demuestra un desempeño competente, evidenciando el logro de los elementos básicos del indicador, pero con omisiones, dificultades o errores.
* **Desempeño incipiente (30%):** Presenta importantes omisiones, dificultades o errores en el desempeño que no permiten evidenciar los elementos básicos.
* **Desempeño no logrado (0%):** Ausencia o incorrecto desempeño.
